# Постоянная ссылка на ручную сетку ISTe — этап подготовки

В отличие от `/tournaments/share#s=...` (статический снимок), будущая постоянная ссылка будет обращаться к записи в Supabase. При изменении результата владелец сможет обновить **ту же запись**, сохранив одну и ту же ссылку.

## Что подготовлено
- Таблица `iste_manual_bracket_shares` с непрогнозируемым UUID, владельцем, JSON снимком, номером редакции и датой обновления.
- Табличный доступ `anon` и `authenticated` отозван; RLS включён. Доступ — только через выделенные RPC.
- RPC `iste_manual_bracket_owner_upsert`: требует реальную авторизацию владельца и MFA AAL2; защищает изменение редакцией `revision` от перезаписи устаревших данных.
- RPC `iste_manual_bracket_public_read`: доступно анонимное **чтение** сетки только по известному UUID. Создание/редактирование без роли владельца недоступны.

## Ограничения и порядок внедрения
1. **Не применять эту миграцию к production автоматически**. Сначала прогнать её в DEV и проверить доступ обычных пользователей, владельца без MFA и анонимного чтения.
2. Реализовать отдельные серверные обработчики, которые используют пользовательскую сессию владельца, и добавить **отдельный выключенный по умолчанию** флаг `ISTE_MANUAL_BRACKET_SHARES_ENABLED`; существующий флаг V2 не трогать.
3. Проверять формат снимка также на уровне API (текущий SQL обеспечивает только базовые ограничения полей и размера).
4. Реализовать пользовательский интерфейс публикации, индикацию текущей редакции и публичную страницу с периодическим обновлением.
5. Перед production — повторный свежий бэкап, изолированный тест восстановления, проверка RLS, SQL-привилегий и smoke-тест нового API.

Публичная ссылка **не является секретной авторизацией**, поэтому публикуемый снимок должен содержать только данные, разрешённые для всех зрителей. UUID генерируется сервером автоматически; участникам его вводить не нужно.
